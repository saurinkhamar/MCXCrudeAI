# Agent roles and editing guide

When `AGENT_MODE=auto` and `GOOGLE_API_KEY` is configured, `backend/mcx_ai/adk_agents.py` builds and invokes a Google ADK graph during signal generation. Each role prompt receives the current Pydantic JSON Schema as its explicit output contract; the model returns JSON and Python validates it locally. Malformed specialist reports are marked insufficient so they cannot supply unsupported evidence; malformed Orchestrator proposals fail closed. Without the key, deterministic analysis is selected. `AGENT_MODE=adk` requires credentials and fails closed when the workflow cannot return valid outputs; `AGENT_MODE=deterministic` disables model calls. A Gemini consumer subscription does not imply API entitlement; configure API access separately if desired.

Prompt files under `backend/mcx_ai/prompts/` define Orchestrator, Fundamental Analyst, Technical Trend and Structure Analyst, and Technical Momentum and Setup Analyst roles. Edit those files directly and keep them version-controlled. Each specialist writes its schema-validated `AgentReport` to `fundamental_report`, `trend_report`, or `momentum_report` in shared ADK session state; the sequential Orchestrator reads all three and writes a `SignalProposal` to `signal_decision`. Keep schemas in `backend/mcx_ai/schemas.py` stable. `data_status` must be `insufficient` when evidence is missing. Never place risk authority or execution tools in an agent. Python is the deterministic risk authority and a human must approve each signal. Confidence is a model score, not a calibrated probability.

For live analysis, the Fundamental Analyst receives recent relevant EIA **Today in Energy** and **Press Releases** RSS headlines/summaries from a persistent SQLite cache. The cache refreshes hourly by default (`FUNDAMENTAL_REFRESH_MINUTES`) and the last successful reports are reused between refreshes and through temporary feed failures. Each item carries its source URL and original publication timestamp. Hourly polling does not mean the source publishes hourly. Historical replay deliberately receives no current fundamentals, avoiding future-information leakage.

To change a role, update its prompt and corresponding `Agent` definition. To change models, update `GOOGLE_MODEL` locally. `AGENT_OUTPUT_TOKENS` bounds output length. Per-role enable/disable controls are not implemented; all three analysts run together to ensure the Orchestrator receives the complete contract.

The step-by-step CSV replay can invoke the same graph at each selected historical candle. Each invocation sees only the candle history through that timestamp and is labeled experimental. It makes four model calls per click (three parallel specialist calls and one orchestration call), so a long replay may consume API quota. Use `AGENT_MODE=deterministic` for no-model replay.
